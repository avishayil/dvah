Damn Vulnerable Agent Harness

Make your AI agents safe — by breaking one and fixing it.

DVAH is a hands-on lab for engineers who ship agents that call tools, spend money, or touch prod. Take a deliberately-insecure agent runtime, exploit a real architectural bug, see exactly why it happened, patch it, and prove the fix holds — no security background needed.

How a lab works

Every lab is the same loop. It takes about ten minutes and you steer the whole way.

  1. Step 1
    Exploit
    run the attack and watch it succeed
  2. Step 2
    Trace
    see step-by-step why it worked
  3. Step 3
    Patch
    edit a few lines in the runtime
  4. Step 4
    Prove
    tests + hidden mutations go green

Not a tutorial — a harness

The runtime is real, the bugs are architectural, and your fix has to earn it.

◈

Invariant-first grading

You aren't graded on style. Each lab pins a security rule an agent runtime must never break, and your fix has to make that rule hold.

◎

Adversarial by design

A chaos engine mutates the attack after you patch. A fix that only handles the demo won't survive the unseen variations.

≣

Live security trace + two scores

Every action flows through authorize → approve → run → record. Run labs deterministically, against a live model, or replay a recording — and read two scores: the deterministic runtime security verdict and what the model actually did.

The 14 rules a safe runtime never breaks

what's an invariant? →
INV-01Check permission for every action right before it runs. INV-02A sub-agent can't be more powerful than its parent. INV-03Human approval is tied to the exact action, not the plan. INV-04Secrets never reach the model's context. INV-05Every value keeps a "where did this come from?" tag. INV-06Untrusted data can't become instructions; delegation can't mint budget. INV-07A skill update can't silently gain new powers. INV-08Every action is attributable to a person + agent + delegation chain. INV-09Authority is re-checked for long-running work; revocation takes effect. INV-10Memory stays per-tenant and never acts as an instruction. INV-11Approval is tied to the tool's identity/version. INV-12Security checks are atomic — races can't sneak past a limit. INV-13Authorization checks the exact operation, not just the tool. INV-14Runtime boundaries are contained — the harness limits egress and pins tool-server identity.
